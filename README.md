# flash_card — 笠翁对韵闪卡

将 `data/` 目录下的 JSON 闪卡数据转换为**可打印的"笠翁对韵"闪卡**。交付物为 HTML 文件：在浏览器中打开，按 `Ctrl+P` 即可直接打印。

---

## 1. 项目目标（一句话）

> 读取 `data/*.json` 中的闪卡数据，生成排版精美、打印友好的 HTML 闪卡页面，供浏览器打开后 `Ctrl+P` 打印成实体卡片使用。

**交付物定义（其他 AI 工具执行任务时必须满足）：**

| 项 | 要求 |
|---|---|
| 格式 | 单个或多个 HTML 文件 |
| 使用方式 | 浏览器双击打开（`file://` 协议可运行，无需本地服务器、无外部网络依赖） |
| 打印 | 按 `Ctrl+P` 后打印预览正常：A4 纸张、页面方向明确、卡片不被分页截断 |
| 内容 | 与 `data/` 中 JSON 数据完全一致，不增删、不改写 |

---

## 2. 项目背景

《笠翁对韵》是明末清初文学家李渔（号笠翁）编写的国学声律启蒙读物，教儿童学习对仗、用韵与诗词格律。全书按《平水韵》平声三十韵编排，分上下两卷，每卷十五韵部：

- **上卷**：一东、二冬、三江、四支、五微、六鱼、七虞、八齐、九佳、十灰、十一真、十二文、十三元、十四寒、十五删
- **下卷**：一先、二萧、三肴、四豪、五歌、六麻、七阳、八庚、九青、十蒸、十一尤、十二侵、十三覃、十四盐、十五咸

每韵部含若干则对文（如"天对地，雨对风。大陆对长空……"），由单字对到十一字对，逐级递进，是儿童学对仗、记典故、练语感的经典教材。

本项目的数据即来自对该书的解析：将原文中的**对仗意象词**逐词提取为闪卡，每张卡包含该词的出处原文、位置逻辑与释义分析。

## 4. 数据格式（JSON Schema）

`data/*.json` 均为 **UTF-8 编码的 JSON 数组**，数组元素为卡片对象，字段说明如下：

> **卡片结构**：每张卡为「图片页 + 信息页」双面结构——**正面为图片页**（`image`），**背面为信息页**（`keyword` / `logic` / `source` / `analysis` / `category`）。

| 字段 | 类型 | 说明 | 示例 |
|---|---|---|---|
| `image` | string[] | 卡片正面图片路径数组（可含多张，供渲染时轮播/选择）。**图片生成前为空数组 `[]`**，生成后填入路径 | `["testdata_images/tian_1.png", "testdata_images/tian_2.png"]` |
| `keyword` | string | 卡片关键词：从原文提取的对仗意象词（卡面主标题） | `"天"` |
| `logic` | string | 该词在原文对句中的位置与逻辑（上联/下联/中句 + 含义概括） | `"上联'天'代表苍穹高远"` |
| `source` | string | 出处原文：《笠翁对韵》原句（可含多句） | `"天对地，雨对风"` |
| `analysis` | string | 释义与意象分析（卡片背面/说明文字） | `"天空高远广阔，是自然空间的典型意象"` |
| `category` | string | 所属韵部，命名规范为 `卷上·X` 或 `卷下·X` | `"卷上·一东"` |

**示例（`data/testdata.js` 第一张卡，`testdata.json` 不含 `image` 字段）：**

```json
{
  "image": ["testdata_images/tian_1.png", "testdata_images/tian_2.png", "testdata_images/tian_3.png", "testdata_images/tian_4.png"],
  "keyword": "天",
  "logic": "上联'天'代表苍穹高远",
  "source": "天对地，雨对风",
  "analysis": "天空高远广阔，是自然空间的典型意象",
  "category": "卷上·一东"
}
```

> **JS 版数据**：`data/testdata.js` 为 `testdata.json` 的 JS 形式（全局变量 `testdata`，已按上述 schema 补入 `image` 字段）。`file://` 协议下 `fetch` JSON 受限，故提供 JS 版供 HTML 以 `<script src="data/testdata.js"></script>` 直接引用，无需本地服务器。

**数据现状统计（`data/data.json`，共 151 张卡）：**

| 韵部 | 卡片数 | 韵部 | 卡片数 |
|---|---|---|---|
| 卷上·一东 | 20 | 卷上·六鱼 | 22 |
| 卷上·二冬 | 20 | 卷上·七虞 | 10 |
| 卷上·三江 | 16 | 卷上·八齐 | 12 |
| 卷上·四支 | 18 | 卷上·九佳 | 6 |
| 卷上·五微 | 18 | 卷上·十灰 | 9 |

> 现状：数据仅覆盖上卷前十个韵部（一东~十灰）。十一真~十五删及整个下卷暂缺，属未来扩展方向。

## 5. 任务规格（给执行 AI 的操作指令）

### 5.1 输入
- 正式数据：`data/data.json`（151 张卡）
- 测试数据：`data/testdata.json`（5 张卡，用于开发阶段快速验证）
- 测试数据 JS 版：`data/testdata.js`（5 张卡，含 `image` 字段，供 HTML 以 `<script>` 方式直接引用）

### 5.2 输出
- 建议输出目录：`output/`
- 建议命名（可直接采用）：
  - 全量页面：`output/liweng_duiyun_flashcards.html`
  - 测试页面：`output/test_flashcards.html`（可选）
- 如需拆分文件（如按韵部一页一文件），请在 README 中记录约定，保持命名可预测。

### 5.3 页面设计要点
1. **卡片内容映射**（双面结构：正面图片页 + 背面信息页）：
   - `image` → 正面图片页（整面展示图片；值为空数组 `[]` 时显示占位图/占位文字，图片生成后替换；数组含多张图时轮播展示）
   - `keyword` → 背面卡面主标题（大字、醒目，如 40~60px）
   - `source` → 出处原文（与 keyword 一同展示，如"天对地，雨对风"）
   - `logic` → 位置逻辑说明（可作副标题）
   - `analysis` → 释义分析（卡面正文）
   - `category` → 分组依据（按韵部生成章节标题，如"卷上·一东"）
2. **布局**：按 `category` 分组展示；单张卡片建议为"标题 + 出处 + 释义"的竖版结构；每页（A4）容纳 6~8 张卡片为宜，卡间留裁剪余量（如虚线裁切线或页边距留白）。
3. **打印友好**：
   - 必须含 `@media print` 样式，`page-break-inside: avoid` 防止卡片被分页截断；
   - 设置 `@page` 尺寸（A4）与页边距；
   - 屏幕上隐藏非打印元素（如按钮、操作提示）。
4. **技术约束**：
   - 所有样式建议内联于 HTML（`<style>`）中，资源不依赖外网（不引用 CDN 字体/库），保证离线 `file://` 打开可用；
   - 文件必须 UTF-8 编码，HTML 需声明 `<meta charset="utf-8">`（避免中文乱码）；
   - 无需 JavaScript 也能完整打印（打印依赖尽量纯 CSS 实现）。

### 5.4 验收标准（执行完成后自查）
1. 浏览器打开 HTML 无报错，151 张卡全部渲染，内容与 JSON 逐字段一致；
2. `Ctrl+P` 打印预览正常：A4 版面、中文不乱码、无卡片被分页截断；
3. 页面直接双击（`file://`）即可使用，断网可打开。

## 6. 开发约定

- 数据文件一律 **UTF-8 编码**，禁止改源数据（`data/` 只读，生成逻辑写在 HTML/脚本侧）。
- `category` 命名严格遵循 `卷上·X` / `卷下·X`（X 为中文数字韵部名）。
- 交付物命名使用 ASCII 小写加下划线（如 `liweng_duiyun_flashcards.html`），避免跨平台文件名问题。
- `image` 字段为路径数组：图片生成前为空数组 `[]`；生成后统一填入路径（如 `testdata_images/tian_1.png`），多张图全部保留在数组中，并保持 `testdata.js` 与 JSON 数据 schema 同步。
- 后续扩展方向：补齐 `十一真`~`十五删` 及卷下十五韵的数据；如需音频/拼音字段，先在 README 中补充 schema 说明。

## 8. 经验沉淀（实操记录，供后续任务参考）

### 8.1 闪卡图片生成工作流（2026-08-02 已跑通，2026-08-03 流程更新）

输入一个闪卡 JSON 数据文件（如 `data_260802.json`，文件名可变），产出三件套，**命名以输入文件名为前缀统一**：

| 产出 | 说明 |
|---|---|
| `<base>_images/` | 生成的图片目录（如 `data_260802_images/`） |
| `<base>.json` | **更新原数据文件**：每张卡写回「图片提示词」+ `image` 路径数组（构建脚本 `build.js` 写回，不再生成 JS 版数据文件） |
| `<base>-review.html` | 审核工具：**上传 JSON 加载** → 编辑 → 导出 JSON 覆盖源文件（样式同旧版编辑工具） |

其中 `<base>` = 输入文件名去掉扩展名（`data_260802.json` → `data_260802`）。

> **流程变更**：旧流程产出 `<base>.js`（`const xxx = [...]`）+ `<base>.html`（`<script src>` 加载）已取消；图片结果直接写回 json，审核页通过 `<input type=file>` 上传 JSON（file:// 下 fetch 受限）。

**图片提示词模板**（统一风格，保证横版无文字）：

```
国风儿童插画：<围绕 keyword + analysis 描绘 60~100 字场景>，构图大气留白，色彩明亮清新，扁平卡通风格，圆润可爱线条，适合儿童闪卡横版构图，无文字
```

**生成与下载**：通过调试端口 9700 的浏览器（豆包，用户已登录）执行：
- CDP 连接：`chromium.connectOverCDP('http://localhost:9700')`，取 `url.includes('doubao.com')` 的页面
- 提交：点「图像生成」按钮（确保图像模式）→ 编辑器 `div.tiptap.ProseMirror`（兜底 `textarea.semi-input-textarea`）→ 输入提示词 → 回车
- 等待：轮询 `img[src*="rc_gen_image"]`，新 URL 数量稳定 8 秒且无"正在生成"文本即完成（超时 180s）
- 下载：点击缩略图打开编辑面板 → 点「保存」→ 捕获 download 事件 → `saveAs` 到 `<base>_images/<拼音>_<序号>.png`
- 环境：Windows 需 `$env:NODE_PATH = "C:\Users\bruce\AppData\Roaming\npm\node_modules"` 才能 require playwright

### 8.2 <base>-review.html 审核工具（审核入口）

- 用途：上传 JSON → 展示 + 编辑 + 最终审核卡片数据，**非最终交付物**
- 数据流：**点击「上传 JSON」选择 `data/<base>.json`**（`<input type=file>` + FileReader，初始为空状态引导，**数据一律不自动加载**；有草稿时仅显示「恢复上次草稿」入口，点击才载入）→ 编辑 → `localStorage` 草稿自动保存（刷新不丢）→ 点「导出 JSON」下载/复制内容 → 手动覆盖源文件
- 功能：增删图片（选择目录枚举/手动输入）、设为默认（数组第一张为默认）、编辑全部字段（含图片提示词）、新增/删除卡片、导出 `<base>.json`

### 8.3 已知坑与对策（务必遵守）

| 坑 | 现象 | 对策 |
|---|---|---|
| 豆包每轮生成 1~4 张不等 | 非固定 4 张 | 以实际检测到的新 URL 为准，不假设数量 |
| 虚拟滚动 + 懒加载 | 未加载的 img src 是 `data:image/svg` 占位；滚动会卸载远处图片，重新出现时被误判为"新图" | 检测前滚动到底部；下载后**全量 MD5 去重**，重复文件删除并重下 |
| 点「保存」下载错图 | 编辑面板停留在上一张图的会话中，保存的是旧图 | 下载前核对面板内 img 的 URL 基名与目标一致 |
| 草稿路径残留 | 目录重命名后（如 `images/` → `testdata_images/`），localStorage 旧草稿仍指向旧路径 → 全部裂图 | 编辑工具加载草稿时自动迁移旧前缀（模板已实现）；用户浏览器中的旧草稿需手动清除 |
| JSON 数据格式错乱 | 旧流程依赖 `<base>.js` 全局变量（`const data260802 = [...]`），已废弃 | 现流程：数据写回 `<base>.json`，审核页「上传 JSON」加载（`<input type=file>` + FileReader），导出 JSON 覆盖源文件；`<base>-review.html` 初始为空状态引导 |
| JSON 导出中文变 `\uXXXX` | JSON.stringify 默认转义非 ASCII | 导出时用正则还原 `\u([0-9a-fA-F]{4})` 为原始中文 |
